\section{The overfitting problem}

Overfitting can take different forms. In this thesis, the term refers specifically to
optimization-induced overfitting in trading strategy backtests. This is the risk that a strategy
appears strong because its parameters were selected to match noise or path-specific patterns in the
IS period, rather than because the strategy captures a stable market effect. \citet{white2000}
formalizes this data-snooping problem: when many alternatives are tested on the same sample, strong
historical performance can arise by chance. \citet{sullivan1999} apply this problem directly to
technical trading rule performance, while \citet{bailey2017} study the same issue in the specific
context of backtest overfitting.

A naive approach to strategy development would be to optimize a strategy on the full available
historical dataset and then deploy the best-performing configuration. This is problematic because
the same data is used both to choose the parameters and to judge the quality of the strategy. If
many parameter combinations are tested, some of them are likely to look good by chance, even if the
underlying rule has little predictive value. Such a configuration may produce an impressive
backtest, but fail when applied to new market data.

In this setting, overfitting can therefore be understood as a loss of generalization caused by
parameter selection. The strategy becomes too adapted to the noise, anomalies, and specific sequence
of events observed in the historical sample. As a consequence, the more a strategy is overfitted,
the less likely it is that its backtested performance will be repeated in the future.

A common response to this issue is to split the historical data into two parts. The first part,
usually called the in-sample period (IS from now on), is used to develop and optimize the strategy.
The second part, called the out-of-sample period (OOS from now on), is kept separate and used only
after the parameters have been selected. In this thesis, the benchmark approach uses a 70\%
in-sample and 30\% out-of-sample split, where the out-of-sample period corresponds to the most
recent part of the original historical series. This reflects the practical objective of testing
whether a strategy optimized on the past would have remained effective on later unseen data.

\section{Rationale}

Given the overfitting problem discussed above, the standard practice is to separate optimization and
evaluation through an IS/OOS split. The strategy is optimized on the IS period, the parameters are
frozen, and the final evaluation is performed on the OOS period. This is useful because it creates a
cleaner test of whether the optimized parameters generalize to unseen data.

This thesis proposes an alternative optimization input. Instead of optimizing only on the single
historical IS path, the IS period is used to generate several synthetic market paths. The strategy is
then optimized using average performance across those paths. The purpose is to test whether this can
reduce the loss of generalization created by overfitting.

\citet{bailey2017} address a related but different part of the problem. Their approach estimates the
probability that a selected backtest is overfit after many alternatives have been tested. This thesis
does not try to estimate that probability directly. Instead, it tests whether changing the
optimization input can lead to parameter choices with smaller IS/OOS deterioration.

This idea is not usually the first approach in strategy optimization. A common objection is that
synthetic random walks may add too much noise and remove too much of the original market structure.
In that case, the optimizer would no longer learn from market behaviour, but from artificial
randomness. This thesis addresses that concern by using synthetic paths that retain randomness while
remaining linked to the original market path by construction.

\section{Research question}

The central question of this thesis is whether a synthetic-market-based optimization procedure can
improve robustness compared with the standard historical in-sample optimization approach. Both
methods use the same general optimization logic, but they differ in the data on which the
optimization is performed.

In the benchmark case, the strategy is optimized directly on the historical in-sample period. In the
synthetic case, the in-sample period is first used to generate multiple synthetic market paths. The
strategy is then optimized across these generated paths, and parameter selection is based on average
results rather than on one realized historical path. The selected parameters from both approaches
are finally tested on the same real out-of-sample period. This makes the comparison focused: the
objective is not to prove that a strategy is profitable, but to evaluate which optimization
procedure loses less performance when moving from optimization to OOS testing.

\section{Approach and contribution}

The research question requires both a clear testing procedure and code that can run many strategy
tests efficiently. For this reason, I developed a custom research framework composed of a C++
backtesting and optimization engine connected to Python reporting and analysis tools. The C++
component handles the computationally intensive parts of the workflow, including data processing,
strategy simulation, trade reconstruction, and grid-based optimization. Python is used for report
generation and plotting.

The framework is built to compare the proposed method against a clear benchmark. The benchmark is the
standard historical IS/OOS workflow: parameters are selected on the real IS period and evaluated on
the real OOS period. The proposed method keeps the same OOS evaluation, but changes the optimization
input: parameters are selected using the mean result across synthetic IS paths. In both cases, the
same strategy, data split, performance metrics, and OOS test period are used. The main comparison is
therefore the IS-OOS performance gap produced by each method.

The practical relevance of this comparison is capital allocation. An asset manager does not only need
a strategy that performs well in a backtest; they need evidence that the selected parameters are not
mainly the result of fitting noise in one historical sample. A method that reduces the IS-OOS
performance gap would make strategy selection more reliable before capital is allocated. Conversely,
if the synthetic workflow does not reduce this gap, this is also useful information, because it shows
that the additional computational cost is not justified by better OOS robustness in the tested
setting.
